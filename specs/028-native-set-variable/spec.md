## Consumer outcome

A native MCP client inspecting a stopped debuggee can set a named variable in an explicitly supplied variable container and observe the adapter's new value. The request can execute debuggee code or change state; it is neither read-only nor idempotent.

## Contract

- Add `set_variable(debugSessionId, inspectionContextId, variablesReference, name, value)` to the stateful host. Require a nonblank session ID and current inspection context, a positive Int32 container reference, and exact string name and value. Reject other shapes and unknown fields before DAP I/O. Do not infer the current session, container or variable, and do not claim the context proves that the numeric reference was issued.
- Track `supportsSetVariable` from the initialize response and subsequent capabilities events in reader order. A missing or false capability returns fixed `DAP_SET_VARIABLE_UNSUPPORTED` before a write; stale or unavailable inspection context returns fixed `DAP_SET_VARIABLE_REFUSED` before a write. Order admission, capability changes, terminal fencing, request registration and the write using the existing session owner.
- Send one DAP `setVariable` containing only the exact `variablesReference`, `name` and `value`. A current, valid positive response returns `kind: set_variable_success`, the new `value`, nullable `type`, nonnegative `variablesReference` (zero when omitted), and a fresh `inspectionContextId`. Apply the existing complete serialized inspection-response bound, including escaping, without truncation.
- A completed mutation may invalidate prior variable references. Rotate the inspection context in reader order before publishing a correlated response, so requests and replies using the old context cannot be treated as current afterward. The returned reference and new context may be used together while that stopped state remains current. As with existing inspection, the token does not prove the provenance of arbitrary numeric references. Preserve real DAP stop/continue/invalidated events and do not create a stopped-state claim.
- A negative adapter response returns fixed `DAP_SET_VARIABLE_FAILED`; it does not prove the debuggee was unchanged and the prior inspection context is invalidated. A stale post-write response, malformed or oversized result, timeout, EOF or protocol error returns fixed `DAP_SET_VARIABLE_OUTCOME_UNKNOWN`, invalidates the context and drains through the existing lease-release-before-close owner. Do not expose adapter messages or retry automatically.
- Cancellation before writer handoff sends nothing and preserves the session/context. Cancellation during or after a possible write invalidates the context and drains without retry; the debuggee effect remains unknown. A fully validated correlated result may be retained under the existing lifecycle rules. No automatic compensation or rollback is attempted.
- Do not change Python, the published preview, UI input, default selection or release state. Python's implicit session selection and legacy envelope are not claimed as parity.
