# Native DAP frame inspection

## Outcome
An opt-in modern native MCP client with a live, stopped debug session whose DAP initialize response explicitly supports delayed stack-trace loading can explicitly name one opaque session and one thread, receive one bounded normalized page of its DAP frames, and retain the session after a refusal. The installed Python `netcoredbg-mcp` remains the selected default/rollback route and independently proves `PRODUCT_WORKS` as non-selection compatibility.

## Requirements

- **B2-REQ-001 — Closed explicit input:** `get_call_stack` accepts exactly `{debugSessionId,threadId,startFrame?,levels?}`. `debugSessionId` follows B1 opaque lookup policy: it is required, is a string, and must be non-whitespace after trim; a missing arguments object, omitted required field, non-string token, empty/whitespace-only token, extra field, non-integer numeric value, or numeric value outside its stated range returns `invalid_tool_arguments` before DAP I/O. `threadId` is required Int32. `startFrame`, when supplied, is uint32; `levels`, when supplied, is uint32 in `1..256`. Defaults are `startFrame=0` and `levels=20`; `levels=0` is invalid, never DAP's all-frames convention.
- **B2-REQ-002 — Opaque session and explicit thread:** The registry resolves only a currently live opaque native `debugSessionId`; every unavailable non-whitespace token returns the existing `DEBUG_SESSION_NOT_FOUND` result without token grammar disclosure, ambient scanning, creator/connection ownership, or default-thread selection. The exact supplied `threadId` is the only DAP target.
- **B2-REQ-003 — Capability-gated atomic typed operation:** Only an internal typed `NetCoreDbgSession.GetCallStackAsync` may issue DAP `stackTrace`. A narrow session capability record captures `supportsDelayedStackTraceLoading` from the initialize response and treats only an explicit boolean `true` as permission for B2 finite paging; it is not a generic feature registry and is never exposed. The session's one internal DAP operation/state gate applies lifecycle events and typed admission. A `stopped` event with `allThreadsStopped:true` atomically replaces every prior eligibility token with one all-target token. A `stopped` event whose `allThreadsStopped` is omitted or false atomically invalidates every existing all-target and per-target eligibility token, then installs exactly one new per-target token for its supplied `threadId`; if that partial event omits `threadId`, it installs no token and admits no target. For a `continued` event, `allThreadsContinued` omitted or true atomically invalidates the all-target token and every per-target token. `allThreadsContinued:false` with a supplied `threadId` atomically invalidates eligibility only for that named target and preserves unrelated target eligibility; an all-target representation must exclude the named continued target. `allThreadsContinued:false` without `threadId` fails closed by atomically invalidating every eligibility token, making no target eligible, and retaining no unknown token. `GetCallStackAsync` holds the gate from stopped-plus-capability/token checking through correlated `stackTrace` registration and write, and captures the requested target's private token only for that request. At the correlated response's serial-reader dispatch position, the single DAP reader validates the request-local captured target token under `_stateGate`; it does not reacquire the admission gate. If a target continuation or resume→restop invalidated or replaced the capture, it returns exactly `DAP_STACK_TRACE_REFUSED`, publishes no frames, and preserves the live session. It never exposes or caches an epoch or eligibility result, and no registry-level precheck is permitted. An event racing admission therefore writes before that event under the former token or returns `DAP_STACK_TRACE_REFUSED` with no post-event `stackTrace` write.
- **B2-REQ-004 — Correlated normalized success:** A success requires a correlated `stackTrace` response with an object `body` and `stackFrames` array of at most 256 entries. Every frame has int32 `id`, string `name` of at most 1,024 UTF-8 bytes (empty is valid), and integer `line` and `column` each in `0..9007199254740991`, inclusive—the vendored DAP `uint64` safe-integer maximum. Negative, non-integral, or above-maximum `line`/`column` values are protocol errors. `source`, when present, is an object and its optional `path` is a string of at most 4,096 UTF-8 bytes. An absent source or source object without `path`, including a sourceReference-only object, is valid and normalizes to `source:null,line:0,column:0`; no source filesystem read occurs. Optional `totalFrames` is uint32. The normalized projection contains only `id`, `name`, `source`, `line`, `column`, and optional `totalFrames`; it deliberately omits raw `sourceReference`, all remaining DAP fields, and source context.
- **B2-REQ-005 — Complete native MCP result:** Every application outcome is a `CallToolResult` with `resultType:"complete"`; `structuredContent` is the complete normalized object and the single `{type:"text"}` content item is its identical JSON serialization. `{kind:"call_stack_success",frames:[...],totalFrames?}` has `isError:false`. `{kind:"dap_stack_trace_refused",error:"DAP_STACK_TRACE_REFUSED"}` and `{kind:"dap_stack_trace_protocol_error",error:"DAP_STACK_TRACE_PROTOCOL_ERROR"}` have `isError:true`. No B2 result reveals raw DAP `body`/`message`, Python `data`/`state` fields, retries, or source context. Other tools' application and protocol outcomes remain unchanged.
- **B2-REQ-006 — Bounds and protocol failure:** The UTF-8 encoding of the complete success `structuredContent` is at most 262,144 bytes, inclusive; the duplicated text item and outer `tools/call` envelope do not count. A response at the boundary is success; any oversized serialized success, frame-count excess, invalid type, malformed body, wrong command/correlation, timeout, or reader failure is the redacted protocol error, contains no partial frames, and triggers existing slot eviction/drain.
- **B2-REQ-007 — Existing lifecycle ownership:** An admitted operation holds the existing registry `SessionSlot` lease from before typed stopped-state/DAP work until `finally` release. The existing `SessionSlot` alone owns admission closure, token removal, one shared cleanup task, deadline abort, stop, and dispose. A refusal preserves token/session usability. A protocol failure releases its own lease before joining the existing close-and-drain task; later operations receive `DEBUG_SESSION_NOT_FOUND`. No registry, frame cache, generic capability registry, or cleanup owner is added.
- **B2-REQ-008 — Frame identity and compatibility:** Frame ids are unmodified adapter ids, unique across threads, unpersisted, and may be used only by a later scopes slice that establishes its own frame-id lifetime contract. Python is a behavioral oracle for core frame fields and 0/20 defaults only; B2 does not import its optional-thread fallback, synchronization retry, source-context read, error envelope, package/default selector, or public contract. The final evidence includes the retained installed-Python `PRODUCT_WORKS` journey as non-selection proof; no release or publication action belongs to this increment.
- **B2-REQ-009 — Admission and current-candidate evidence:** `B2-G0` is a fresh independent pre-implementation recheck of this corrected four-artifact packet; this repair supersedes the prior incomplete recheck and cannot satisfy the gate itself. Only a terminal `B2-G0` verdict admitting the all-thread/named-partial `continued` branches, request-local token-current response publication, strict partial-stop replacement, and safe-integer frame bounds permits implementation. Before final B2 evidence, the exact candidate runs a current-candidate B1 baseline of `GetThreadsContractTests`, `SessionSlotContractTests`, `SessionSlotLifecycleTests`, `NetCoreDbgSessionTests`, and `StructuredContentSchemaParityTests` alongside the B2 focused gates. Every executed group records its actual nonzero denominator; B1's pre-merge 52/52 observation cannot be recycled. B2 is S2: T04 applies the installed platform `security-review` contract to closed input/token lookup, DAP framing, capability/stopped/continued admission, token-current response publication, response bounds/redaction, and cleanup, and writes its durable receipt only to root `.agent/runs/b2-native-frame-inspection/security-review.md`.

## Scenarios

1. A valid opaque live token, explicit Int32 thread id, omitted page fields, and an initialize response with `supportsDelayedStackTraceLoading:true` while stopped produce one `stackTrace` request with `startFrame:0` and `levels:20`, a bounded `call_stack_success`, and a session that remains usable for `get_debug_state` and `stop_debug`.
2. A valid request with explicit `startFrame` and `levels` in range forwards that exact bounded page. The response may contain fewer frames than requested and optional `totalFrames`; it never returns more than 256 normalized frames.
3. An otherwise valid stopped request from an initialize response that omits or sets `supportsDelayedStackTraceLoading:false` produces exactly `DAP_STACK_TRACE_REFUSED` and zero `stackTrace` writes. Missing arguments, omitted `debugSessionId` or `threadId`, invalid numeric forms/ranges, `levels:0`, whitespace token, or an extra field produces `invalid_tool_arguments` and zero DAP requests. An unavailable valid non-whitespace token produces `DEBUG_SESSION_NOT_FOUND` and zero DAP requests.
4. A controlled fixture owns RED coverage for continued admission and response publication. After a stopped state makes targets A and B eligible, `continued` with `allThreadsContinued` omitted and with it true each atomically invalidate both targets: each call refuses with zero post-event `stackTrace` writes. A held response whose `stackTrace` was written before either all-thread continuation is released after the event; it returns `DAP_STACK_TRACE_REFUSED`, publishes no frames, and preserves the session. With `allThreadsContinued:false` and named target A, only A is invalidated: A refuses with no write while unrelated B remains eligible and can write `stackTrace`. With `allThreadsContinued:false` but no `threadId`, the transition fails closed: A and B both refuse, no target is made eligible, and no unknown token remains. The fixture also holds a response across target A's continuation followed by A's partial restop; the replacement token does not validate the captured request, so it refuses with no frames while the new A token remains available only to a newly admitted request. Separately, it proves stopped strict replacement: after all-stop, a partial stopped event for target A invalidates all-target eligibility and admits only A; after target A resumes, a partial restop for A installs only A's new token. In both transitions, unrelated target B receives no `stackTrace` write. A partial stopped event without `threadId` installs no token and admits no target. A correlated DAP `success:false`, including not-stopped refusal, also produces exactly `DAP_STACK_TRACE_REFUSED`, exposes no raw adapter data, and leaves the token usable.
5. A frame with empty `name` is valid. A frame without source or with a source object absent `path`, including sourceReference-only, normalizes to `{source:null,line:0,column:0}` and reveals no raw source reference. `line` and `column` at `9007199254740991` are valid; above-range, negative, non-integral, invalid id/totalFrames, invalid types, oversize name/path, or more than 256 frames are protocol errors.
6. A malformed/wrong-command/timeout/reader failure/size excess produces exactly `DAP_STACK_TRACE_PROTOCOL_ERROR`, no partial frames, bounded cleanup, then `DEBUG_SESSION_NOT_FOUND`. The 262,144-byte structured-content boundary succeeds; 262,145 bytes fails.
7. The exact candidate proves all B2 focused gates plus the named current-candidate B1 baseline with actual nonzero denominators. The native executable is not selected by the Python CLI: the installed-Python journey named in `specs/006-a1-local-preview/quickstart.md` still reaches `PRODUCT_WORKS` without package, selector, or configuration reversal.

## Exclusions

Source-context filesystem reads, scopes, variables, frame remapping/persistence, consumption of `sourceReference`, execution control, breakpoints, attach, generic DAP forwarding, DAP format options, generic capability discovery/registry expansion, bridge/UI work, Python retirement or changes, selector/default changes, release, and publication.
