# Native DAP Pause

Status: implemented with passing controlled source checks; real-debugger consumer proof is partial, and integration and delivery remain pending. This additive source slice advances the .NET replacement; Python remains the installed default and rollback. It does not complete migration, installed delivery, or full legacy wire parity.

## Consumer outcome

A native MCP client can request that a live debuggee pause, including while `continue_execution` is waiting for the next stop. The pause call returns when the DAP adapter acknowledges or refuses its request. Only a separately observed DAP `stopped` event establishes stopped state and inspection authority; an acknowledgement alone is not a completed stop.

## Public contract

- Add `pause_execution(debugSessionId, threadId?)`. `debugSessionId` is required, a nonblank string, and otherwise opaque; `threadId` is optional, nullable, and otherwise an Int32. Reject boolean, fractional, and out-of-range thread IDs, unknown fields, and blank or non-string session IDs before DAP I/O. A nonblank unknown or retired session uses the existing `debug_session_not_found` result.
- Preserve Python's actual selection rule: a nonzero explicit input selects that exact thread; omitted, null, or explicit zero uses the current observed thread when one exists. A current thread ID of zero is a valid selection. If current is null, issue at most one bounded DAP `threads` request and select its first returned ID, including zero, without sorting. Empty threads returns `DAP_PAUSE_NO_THREADS` without a pause write. After discovery, recheck lifecycle and use a newly observed current thread if present; do not retry a refused or disappeared target. This final recheck can differ from Python when a current-thread event arrives during discovery; full race-by-race legacy parity is not claimed.
- Use the existing bounded threads parsing/limits and the same debug session. A DAP `pause` carries the selected `threadId` unchanged. No generic DAP forwarding, fallback to another adapter, or synthetic event is added.
- Positive DAP acknowledgement returns `pause_acknowledged` with the selected `threadId`; it does not assert a stopped state, reason, event thread ID, or all-thread stop. A negative acknowledgement returns a fixed `DAP_PAUSE_REFUSED` result. A terminal event observed before an acknowledgement returns `pause_terminal` with only observed terminal/exit fields. Deadline expiry returns `dap_pause_timeout` / `DAP_PAUSE_TIMEOUT`; malformed or uncertain protocol exchanges return `dap_pause_protocol_error` / `DAP_PAUSE_PROTOCOL_ERROR`. These fixed errors do not expose raw adapter messages or stderr. All complete results preserve the native structured-content/text mirror and schema contract.
- Pause is accepted for a live session even if its latest event is null or stopped, matching Python's lack of a synthetic already-stopped gate. Pause must not clear or invent stopped/frame authority merely by admission or ACK. Reader-ordered `stopped`, `continued`, invalidation, and terminal events remain the sole owners of lifecycle and inspection state.
- Use a separate bounded pause reservation. Permit one pause alongside an already committed `continue_execution`, including while its ACK or next stop is pending; do not cancel, replace, or consume the continue record. A real stopped event remains visible to both the lifecycle reader and the existing continue waiter. A second concurrent pause and a new continue/step while pause is active refuse without DAP I/O. An already active `step_over` refuses pause in this slice; do not change step semantics or claim full non-stop parity.
- Serialize the eligibility/lifetime check, pending registration, and actual DAP write with the existing admission/write ownership; release the reader-shared admission gate before waiting for thread discovery, an ACK, or an event. A single absolute request deadline covers optional discovery and pause ACK; no phase resets it. Terminal/closing is monotonic: a later continue finalization or reader callback must never reopen a session fenced by an uncertain pause.
- Distinguish cancellation before writer handoff from a possibly transmitted frame. Before handoff, release the reservation and preserve the session. After write start without a fully committed frame and valid ACK, fence and drain through the existing session/slot owner; do not retry. A fully committed read-only `threads` frame can be abandoned safely while its reply is pending, but an uncertain/partial frame cannot. After a committed pause and valid ACK, caller cancellation alone does not undo or replay it; subsequent events remain reader-owned. Malformed responses, a wrong command for a matched request, EOF, and ambiguous writes use fixed protocol errors and the existing drain owner.
- Correlate responses by `request_seq` and command. An independent concurrent `get_threads` request may use the same command with a different sequence; accept valid out-of-order replies without settling another request. Ignore nonpending `threads` or `pause` responses when handling pause: a `threads` response may be late from an abandoned read-only request, including an ordinary `get_threads`, and cannot safely be attributed to the active pause. If the active request never receives its own response, its original deadline yields the fixed timeout outcome and the phase-specific retention or drain disposition. Do not retain an unbounded history of abandoned sequences. Preserve the existing contracts for other DAP commands.
- Session retirement, stop, and host shutdown retain the existing lease/grace/abort model. Release an active lease before joining close/drain. Never resurrect a token or inspection context through a late response. An admitted lease may complete during the existing grace interval; retirement is not claimed to revoke it instantaneously.

## Verification

1. Before implementation, exercise the missing public route through the real MCP process driver: catalog/schema, invalid arguments, unknown token, and valid omitted/null/zero/boundary values. Add controlled DAP behavior tests for explicit/current/first-thread selection, including input zero versus selected zero, empty/malformed threads, and no unnecessary DAP I/O.
2. Cover ACK without stopped, stopped before ACK, ACK before stopped, stopped→continued→ACK, different/missing event thread IDs, partial/all-thread stops, and terminal ordering. Assert that only real reader events change state or inspection authority.
3. With barriers rather than sleeps, cover pause while continue is committed but ACK-held and while continue is long-polling, concurrent second pause, active step refusal, and the race where pause fences the session before continue finalizes. A closing session must remain closed.
4. Exercise cancellation, timeout, EOF, unmatched responses, wrong commands for matched requests, partial writes, committed-no-ACK, and committed-ACK paths for both optional discovery and pause; verify pending cleanup, lease ordering, session preservation or drain, and no replay. Include a response read before flush/commit publication: an ACK alone cannot establish a fully committed write. Preserve existing continue/step/inspection/output regressions and schema parity.
5. Through a fresh official MCP client, source-built native host, real netcoredbg, and an owned .NET fixture, stop at a real breakpoint, start `continue_execution`, call optional-thread pause while continue is pending, separately observe the real stopped event and managed stack, and repeat with an explicitly observed thread ID. Clean up only the scenario's owned processes. Source-built proof does not establish installed delivery or full migration.

The earlier source-consumer run observed both pause cycles and managed stacks, but its SDK launcher assigned the Windows Job after child start. A later pre-resume-Job-admitted replay observed both cycles, public stop and a drained Job, but its required stdout heartbeat was not observed, so that replay reported `INCOMPLETE`. No single run establishes the complete owned-consumer proof.
