# ADR-006: Add typed native frame inspection with explicit thread and capability-gated bounded paging

## Status
Proposed

## Context
B1 established the native stateful walking skeleton: an opaque `debugSessionId`, registry-owned `SessionSlot` leases, a typed `NetCoreDbgSession.GetThreadsAsync` seam, and a normalized modern MCP result rather than a raw DAP surface. B1 implementation is commit `3ed4b85`, merged by commit `11b69e8`. Its native 52/52 receipt was observed on the dirty pre-merge base, not a post-merge native-test receipt; this ADR does not treat that observation as current-head evidence.

A client can now enumerate threads but cannot locate execution within one. DAP `stackTrace` names one `threadId`; finite `startFrame`/`levels` paging is available to B2 only when the session's initialize response recorded `supportsDelayedStackTraceLoading:true`. DAP permits omitted or zero `levels` to request all frames, but this native boundary must never make an unbounded adapter request. A DAP `StackFrame` has an int32 id, name, source location fields, and many optional presentation/control fields; only the normalized execution-location projection belongs to B2.

This is D2 for this artifact: a wrong native protocol/lifecycle choice would require rework across the MCP dispatcher, typed DAP session, frozen application schema, controlled fixture, and process/lifecycle tests; the boundary is consumed across sessions by future inspection slices.

## Decision

1. Add the additive modern native tool `get_call_stack(debugSessionId, threadId, startFrame?, levels?)`. Its input is a closed object: `debugSessionId` is a required opaque non-whitespace string under the existing lookup policy; `threadId` is a required Int32; `startFrame` and `levels`, if present, are unsigned 32-bit integers. Missing arguments, omitted required fields, non-integral or out-of-range numeric fields, `levels: 0`, or an extra field return `invalid_tool_arguments` before DAP I/O. Defaults are `startFrame: 0` and `levels: 20`; `levels` is at most 256. No ambient thread selection, thread scan, or default-thread fallback is permitted.
2. Retain one narrow native-session capability record populated from the DAP initialize response: `supportsDelayedStackTraceLoading` is true only when the response explicitly supplies boolean `true`. It is not a generic feature registry and B2 does not infer, mutate, or expose it. Only that recorded true value admits B2's finite paging; otherwise `GetCallStackAsync` returns `{kind:"dap_stack_trace_refused",error:"DAP_STACK_TRACE_REFUSED"}` without writing any `stackTrace` request.
3. Add only an internal typed `NetCoreDbgSession.GetCallStackAsync` operation. Its authority is split across exactly two gates. `_callStackAdmissionGate` serializes a call-stack target capture, pending-request registration, and the finite `stackTrace` DAP write; the DAP reader's `stopped`, `continued`, `exited`, and `terminated` handlers take that same gate before changing lifecycle eligibility. `_stateGate` protects lifecycle state, the initialize-derived capability record, and private eligibility-token visibility. While holding admission, `GetCallStackAsync` takes `_stateGate` to require the capability and capture the requested target's private token, then registers and writes the correlated request before releasing admission. A `stopped` event with `allThreadsStopped:true` replaces every prior token with one all-target token. A `stopped` event whose `allThreadsStopped` is omitted or false replaces every prior all-target and per-target token with exactly one per-target token for its supplied `threadId`; if that partial event omits `threadId`, it installs no token and admits no target. A `continued` event is equally mechanical: `allThreadsContinued` omitted or true atomically invalidates the all-target token and every per-target token. With `allThreadsContinued:false` and a supplied `threadId`, it atomically invalidates eligibility only for that named target and preserves unrelated target eligibility; any all-target representation must no longer admit the named continued target. If `allThreadsContinued:false` omits `threadId`, it fails closed by atomically invalidating every eligibility token, making no target eligible, and retaining no unknown token. `exited` and `terminated` likewise clear eligibility under the same admission-then-state ordering. At the correlated response's serial-reader dispatch position, the reader checks the request-local captured target token under `_stateGate` only; it does not reacquire `_callStackAdmissionGate`. A target continuation or resume→restop that invalidated or replaced the capture returns `{kind:"dap_stack_trace_refused",error:"DAP_STACK_TRACE_REFUSED"}`, publishes no frames, and preserves the live session. The implementation exposes and caches neither an epoch nor an eligibility result, and the registry performs no separate state precheck. Therefore a continued, terminal, or partial-stop event racing admission produces either a request written before that event under its former token, or the redacted refusal with no post-event `stackTrace` write. A correlated DAP `success:false` uses the same refusal without a response-body leak.
4. A successful correlated response requires an object `body` with `stackFrames`, at most 256 entries. Each entry must provide int32 `id`, a string `name` no longer than 1,024 UTF-8 bytes (the empty string is valid), and integer `line` and `column` each in `0..9007199254740991`, inclusive (the vendored DAP `uint64` safe-integer maximum). `source`, when supplied, must be an object; its `path`, when supplied, must be a string no longer than 4,096 UTF-8 bytes. An absent source or a source object without `path`—including a sourceReference-only object—is valid and normalizes to `source:null,line:0,column:0`. Invalid types, negative values, and above-maximum values are protocol errors. The public projection is only `id`, `name`, `source`, `line`, `column`, and optional uint32 `totalFrames`; it preserves adapter frame ids without remapping or persistence. It deliberately excludes all other frame and source fields.
5. Every `get_call_stack` application result uses the native complete-result convention: `structuredContent` is the normalized application object; one text content item holds its identical JSON serialization; `isError` is false only for `{kind:"call_stack_success",frames,...}`. A refusal is exactly `{kind:"dap_stack_trace_refused",error:"DAP_STACK_TRACE_REFUSED"}`. Malformed body, wrong command/correlation, timeout, reader failure, or any response-bound/serialized-size failure is exactly `{kind:"dap_stack_trace_protocol_error",error:"DAP_STACK_TRACE_PROTOCOL_ERROR"}`. No result carries raw DAP bodies, messages, source-context reads, Python envelopes, or retries.
6. The 256 KiB ceiling is inclusive and applies to UTF-8 bytes of the complete normalized `structuredContent` success object, not the duplicated text item or enclosing MCP response. A protocol error never returns a partial page. The existing registry-owned `SessionSlot` remains the only cleanup owner: protocol errors evict and drain through its existing close path; refusal leaves the live session usable. Unknown or unavailable non-whitespace opaque tokens retain `DEBUG_SESSION_NOT_FOUND` without scanning.
7. Frame ids are adapter values unique across threads. They are unpersisted and may be used only by a later scopes slice that establishes its own frame-id lifetime contract; B2 neither persists, remaps, selects, nor consumes them. Python remains the default and rollback route. It is an oracle for the basic fields and `startFrame:0`/`levels:20` defaults, not a verbatim protocol promise: B2 deliberately excludes its optional-thread fallback, retries, source-context filesystem reads, and error-envelope behavior.

## Alternatives

| Alternative | Decision | Rationale |
|---|---|---|
| Internal typed `GetCallStackAsync` behind the existing opaque registry and `SessionSlot` | Chosen | Keeps one bounded command while separating admission/write serialization from state/token visibility, preserving reader-order stale-response refusal, correlation, redaction, and cleanup ownership at the native DAP boundary. |
| Generic MCP-to-DAP request forwarding | Rejected | Would make arbitrary DAP commands, payloads, capability variance, and raw adapter failures a public authority surface. |
| Leave call-stack inspection exclusively on the Python route | Rejected | Retains the user gap in the additive native walking skeleton and forces future native scopes work to begin without its typed frame boundary. |

## Consequences and compatibility

The native catalog gains one tool after `get_threads`; the frozen application schema gains only the call-stack input and result variants needed by this tool. Existing lifecycle, thread, and Native Scene contracts remain unchanged. The controlled DAP fixture gains only explicit initialize-capability, stopped/continued all-thread and named-partial invalidation, held-response publication, all-stop/partial-stop admission-race, and `stackTrace` response modes needed to prove this contract.

This is a parallel additive change, not a selector migration. The installed Python wheel remains selected and is replayed as a non-selection proof. B2 does not modify Python, shared frozen behavior outside the new variants, default selection, bridge/UI, execution control, release, publication, or package routing.

## Security and lifecycle boundaries

The native path is `opaque token -> SessionSlot lease -> _callStackAdmissionGate target capture/pending registration/DAP write -> correlated stackTrace -> reader-ordered _stateGate token-current validation -> bounded normalized result`. The DAP reader also enters `_callStackAdmissionGate` before applying `stopped`, `continued`, `exited`, or `terminated`, and then mutates lifecycle state and private token visibility under `_stateGate`; no terminal or lifecycle handler can interleave between capture and write. The response reader does not reacquire admission: its `_stateGate` check at response dispatch makes a request captured before continuation or resume→restop refuse rather than publish stale frames. Closed input prevents accidental ambient selection; the initialize capability record prevents unsupported paging; mechanical all-thread and named-partial continuation transitions prevent resumed targets from publishing stale frames while retaining unrelated targets only after a valid named partial continuation; typed response validation and UTF-8 bounds prevent adapter data becoming an unbounded public payload; redaction prevents DAP messages/bodies from crossing the MCP boundary. The acquired lease spans typed admission, DAP I/O, validation, and result construction. Refusal preserves the session. A protocol failure releases its own lease before joining the existing one-winner close-and-drain sequence, which prevents self-deadlock.

## Admission recheck

`B2-G0` remains a fresh, independent pre-implementation recheck gate over this corrected ADR/spec/plan/tasks packet. This repair supersedes the prior incomplete recheck: it is not evidence that `B2-G0` passed. Implementation admission remains closed until the recheck records its terminal verdict against the all-thread/named-partial `continued` branches, request-local token-current response publication, strict partial-stop replacement, and safe-integer frame bounds.

## Deferred work

Scopes, variables, frame remapping or persistence, source-context reads (including consumption of `sourceReference`), execution control, generic DAP forwarding, UI/bridge work, Python retirement, release, and publication remain outside B2. A future scopes slice must establish its own frame-id lifetime contract.
