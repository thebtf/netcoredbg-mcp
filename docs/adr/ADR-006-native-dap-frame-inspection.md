# ADR-006: Add typed native frame inspection with explicit thread and capability-gated bounded paging

## Status
Proposed

## Context
B1 established the native stateful walking skeleton: an opaque `debugSessionId`, registry-owned `SessionSlot` leases, a typed `NetCoreDbgSession.GetThreadsAsync` seam, and a normalized modern MCP result rather than a raw DAP surface. B1 implementation is commit `3ed4b85`, merged by commit `11b69e8`. Its native 52/52 receipt was observed on the dirty pre-merge base, not a post-merge native-test receipt; this ADR does not treat that observation as current-head evidence.

A client can now enumerate threads but cannot locate execution within one. DAP `stackTrace` names one `threadId`; finite `startFrame`/`levels` paging is available to B2 only when the session's initialize response recorded `supportsDelayedStackTraceLoading:true`. DAP permits omitted or zero `levels` to request all frames, but this native boundary must never make an unbounded adapter request. A DAP `StackFrame` has an int32 id, name, source location fields, and many optional presentation/control fields; only the normalized execution-location projection belongs to B2.

This is D2 for this artifact: a wrong native protocol/lifecycle choice would require rework across the MCP dispatcher, typed DAP session, frozen application schema, controlled fixture, and process/lifecycle tests; the boundary is consumed across sessions by future inspection slices.

## Decision

1. Add the additive modern native tool `get_call_stack(debugSessionId, threadId, startFrame?, levels?)`. Its input is a closed object: `debugSessionId` is a required opaque non-whitespace string under the existing lookup policy; `threadId` is a required Int32; `startFrame` and `levels`, if present, are unsigned 32-bit integers. Missing arguments, omitted required fields, non-integral or out-of-range numeric fields, `levels: 0`, or an extra field return `invalid_tool_arguments` before DAP I/O. Defaults are `startFrame: 0` and `levels: 20`; `levels` is at most 256. No ambient thread selection, thread scan, or default-thread fallback is permitted.
2. Retain one narrow native-session capability record populated from the DAP initialize response: `supportsDelayedStackTraceLoading` is true only when the response explicitly supplies boolean `true`. It is not a generic feature registry and B2 does not infer, mutate, or expose it. Only that recorded true value admits B2's finite paging; otherwise `GetCallStackAsync` returns `{kind:"dap_stack_trace_refused",error:"DAP_STACK_TRACE_REFUSED"}` without writing any `stackTrace` request.
3. Add only an internal typed `NetCoreDbgSession.GetCallStackAsync` operation. `NetCoreDbgSession` owns one internal DAP operation/state gate: applying `stopped` begins or increments an opaque internal stopped epoch, applying `continued` invalidates it, and `GetCallStackAsync` holds the same gate from stopped/capability admission through registration, correlation, and write of the finite `stackTrace` request. It exposes and caches neither the epoch nor an eligibility result. The registry must not perform a separate state precheck. Therefore a continued event racing admission produces either a request written before that event under the former stopped epoch, or the redacted refusal with no post-continued `stackTrace` write. A correlated DAP `success:false` uses the same redacted refusal shape with no adapter body or message exposed.
4. A successful correlated response requires an object `body` with `stackFrames`, at most 256 entries. Each entry must provide int32 `id`, a string `name` no longer than 1,024 UTF-8 bytes (the empty string is valid), and uint64 `line` and `column`. `source`, when supplied, must be an object; its `path`, when supplied, must be a string no longer than 4,096 UTF-8 bytes. An absent source or a source object without `path`—including a sourceReference-only object—is valid and normalizes to `source:null,line:0,column:0`. Invalid types and oversize values are protocol errors. The public projection is only `id`, `name`, `source`, `line`, `column`, and optional uint32 `totalFrames`; it preserves adapter frame ids without remapping or persistence. It deliberately excludes raw `sourceReference`: that adapter-local handle is useful only to a later, separately authorized source-retrieval boundary and would add authority B2 does not need to identify execution location.
5. Every `get_call_stack` application result uses the native complete-result convention: `structuredContent` is the normalized application object; one text content item holds its identical JSON serialization; `isError` is false only for `{kind:"call_stack_success",frames,...}`. A refusal is exactly `{kind:"dap_stack_trace_refused",error:"DAP_STACK_TRACE_REFUSED"}`. Malformed body, wrong command/correlation, timeout, reader failure, or any response-bound/serialized-size failure is exactly `{kind:"dap_stack_trace_protocol_error",error:"DAP_STACK_TRACE_PROTOCOL_ERROR"}`. No result carries raw DAP bodies, messages, source-context reads, Python envelopes, or retries.
6. The 256 KiB ceiling is inclusive and applies to UTF-8 bytes of the complete normalized `structuredContent` success object, not the duplicated text item or enclosing MCP response. A protocol error never returns a partial page. The existing registry-owned `SessionSlot` remains the only cleanup owner: protocol errors evict and drain through its existing close path; refusal leaves the live session usable. Unknown or unavailable non-whitespace opaque tokens retain `DEBUG_SESSION_NOT_FOUND` without scanning.
7. Frame ids are adapter values unique across threads. They are valid only for a later scopes slice in the same stopped epoch; B2 neither persists, remaps, selects, nor consumes them. Python remains the default and rollback route. It is an oracle for the basic fields and `startFrame:0`/`levels:20` defaults, not a verbatim protocol promise: B2 deliberately excludes its optional-thread fallback, retries, source-context filesystem reads, and error-envelope behavior.

## Alternatives

| Alternative | Decision | Rationale |
|---|---|---|
| Internal typed `GetCallStackAsync` behind the existing opaque registry and `SessionSlot` | Chosen | Keeps one bounded command, initialize-capability admission, state/write atomicity, correlation, redaction, and cleanup owner at the native DAP boundary. |
| Generic MCP-to-DAP request forwarding | Rejected | Would make arbitrary DAP commands, payloads, capability variance, and raw adapter failures a public authority surface. |
| Leave call-stack inspection exclusively on the Python route | Rejected | Retains the user gap in the additive native walking skeleton and forces future native scopes work to begin without its typed frame boundary. |

## Consequences and compatibility

The native catalog gains one tool after `get_threads`; the frozen application schema gains only the call-stack input and result variants needed by this tool. Existing lifecycle, thread, and Native Scene contracts remain unchanged. The controlled DAP fixture gains only explicit initialize-capability, stopped/continued admission-race, and `stackTrace` response modes needed to prove this contract.

This is a parallel additive change, not a selector migration. The installed Python wheel remains selected and is replayed as a non-selection proof. B2 does not modify Python, shared frozen behavior outside the new variants, default selection, bridge/UI, execution control, release, publication, or package routing.

## Security and lifecycle boundaries

The native path is `opaque token -> SessionSlot lease -> capability-gated atomic stopped-state/correlated stackTrace -> bounded normalized result`. Closed input prevents accidental ambient selection; the initialize capability record prevents unsupported paging; the session-local operation/state gate prevents a continued event from opening a post-continued write; typed response validation and UTF-8 bounds prevent adapter data becoming an unbounded public payload; redaction prevents DAP messages/bodies from crossing the MCP boundary. The acquired lease spans typed admission, DAP I/O, validation, and result construction. Refusal preserves the session. A protocol failure releases its own lease before joining the existing one-winner close-and-drain sequence, which removes the token and prevents later admission. No generic capability registry, session registry, transport owner, filesystem reader, frame cache, or lifecycle cleanup path is introduced. B2 is S2: T04 applies the installed platform `security-review` contract to closed input/token lookup, DAP framing, capability/stopped admission, response bounds/redaction, continued-race behavior, and cleanup, writing durable evidence only to root `.agent/runs/b2-native-frame-inspection/security-review.md`.

## Deferred work

Scopes, variables, frame remapping or persistence, source-context reads (including consumption of `sourceReference`), execution control, generic DAP forwarding, UI/bridge work, Python retirement, release, and publication remain outside B2. A future scopes slice must establish its own same-stopped-epoch frame-id contract.
